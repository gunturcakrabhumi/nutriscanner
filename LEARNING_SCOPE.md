# Learning Scope — Nutrition Scanner

## Why This Project Exists

Nutrition Scanner is both a product experiment and a controlled learning project inside the user's current **automation engineering / n8n portfolio track**.

The project should broaden the user's exposure to interfaces and problem types without causing uncontrolled expansion into unrelated engineering domains.

## Primary Learning Track

### 1. n8n Orchestration

Practice:

- Webhook triggers
- HTTP requests
- branching
- data transformation
- Code nodes
- AI nodes/API calls
- loops/batching
- error handling
- retries
- workflow modularity

### 2. AI Automation

Practice:

- multimodal input
- structured output
- schema validation
- prompt design
- model/provider abstraction
- multi-step AI workflows
- reconciliation of multiple AI outputs

### 3. Web ↔ Automation Integration

Practice:

- browser upload
- multipart requests
- webhook contracts
- request/response lifecycle
- polling or continuation when needed
- displaying structured automation results

## Secondary Exposure

The project may introduce lightweight concepts around:

- responsive web UI
- HTTP/API contracts
- temporary file handling
- minimal persistence

These are supporting skills, not the primary curriculum.

## Explicitly Out of Learning Scope

Do not turn this project into a course in:

- advanced React/Next.js
- advanced backend frameworks
- microservices
- Kubernetes
- advanced cloud architecture
- native Android
- native desktop applications
- advanced database engineering

If such technology becomes necessary for a concrete MVP requirement, document the reason first and choose the smallest viable solution.

## Scope Guard

Before adding a technology, ask:

> Does this materially improve the automation problem we are solving?

If not:

> defer it.
